# Weekly chapter development task

Requested cadence: every Sunday at 10:00 AM in America/Los_Angeles, following Pacific daylight-saving changes. This file is the prepared task prompt; it does not activate a scheduler.

Work on `enflory/lotr-rpg`. Inspect current `origin/main`, project instructions, the product/reference documents, adaptation notes and open chapter PRs. Resume and finish an outstanding chapter before creating its sequel. Preserve other work and use an isolated branch/worktree. Determine the next logical, complete story unit from the actual implemented endpoint, using the ten-chapter Fellowship outline as guidance. Build the entire chapter through a natural ending, including a playable connection from the existing game and a clear handoff for the next chapter.

Keep the game exploration-first and cohesive with its established procedural pixel art, music, controls, companion movement, interaction cues, dialogue staging and checkpoint system. Follow Tolkien's books as closely as the medium permits. Check source material and distinguish deliberate gameplay compression from book events in adaptation notes. Use original paraphrased dialogue and original music. Do not substitute film-only events, invent lore, or silently skip important book episodes. Choose routine design details autonomously within this scope.

Develop and polish maps, character art, atmosphere, dialogue, optional exploration and chapter-specific mechanics together. Preserve existing saves and provide Continue recovery at significant story beats and interrupted animations. Test the entire new route through ordinary controls, including gates, companions, collision, touch, story choreography and save/reload seams. Use gstack browse for visual browser QA and inspect screenshots. Run the repository's unit tests, lint, typecheck, formatting, production build and complete Playwright suite, fixing regressions. Check the generated game, not just its data.

Update the chapter documentation and adaptation notes, commit the finished changes and open or update a reviewable PR with concise evidence and remaining limitations. Do not merge or deploy automatically. Report the story span, playable changes, validation results and PR link. If source access, authentication, execution limits or permissions block completion, preserve the work and report exactly what remains. If the Fellowship endpoint is complete, report that and request direction before expanding the game's scope.
